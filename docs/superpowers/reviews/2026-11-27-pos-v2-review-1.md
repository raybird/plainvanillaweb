**M5. 主機的信令連線和 peer 用同一個速率上限，加上 `host-online` 一律讓所有直連重建，裝置一多就會陷入重連風暴；這也和「信令斷線不影響直連」的說法矛盾**
- 位置：
  - 主機連線同樣套用每 10 秒 50 則的上限：`server/signaling.mjs:269-278,299`、`server/cloudflare/worker.js:162,171-181`。
  - 每個 candidate 各送一則訊息：`peer-link.js:85-87,109`。
  - 每次主機驗證通過都對所有 peer 廣播 `host-online`：`signaling.mjs:325`、`worker.js:203`。
  - peer 的直連還開著時收到 `host-online` 就立即重連：`peer-link.js:184-192`。
  - 主機收到 4008 後 1 秒就重連：`signaling-client.js:245-258`。
- 實測：本機 headless Chrome 搭配 STUN，每條 PeerConnection 收集到 1 個 host candidate 和 1 個 srflx candidate。主機每回應一台裝置，大約送 answer、2 個 candidate 和 end-of-candidates，共 4 則。換算約 13 台裝置在 10 秒內同時（重新）連線，就超過上限被 4008 關閉。若有 IPv6 或多張網卡，門檻更低。
- 迴圈：
  1. 主機重新整理（A7 的情境）。
  2. 所有裝置同時重新握手，主機超過速率上限，被 4008 關閉。
  3. 主機 1 秒後重連，伺服器又廣播 `host-online`。
  4. 已經接上的裝置全部重連，回到第 2 步。
- 另外，就算裝置不多，主機的 WebSocket 只要重連一次（Quick Tunnel 斷一下、45 秒沒收到訊息），所有正常的 DataChannel 都會被拆掉重建。這違反 ADR 0109 決策 3「信令斷線也不影響已建立的連線」，也和 `docs/solutions/pos-v2.md` 故障模式「信令伺服器斷線…不受影響」不符。文件宣稱「每個房間最多 64 台裝置」，實際做不到。
- 驗證程度：以上靠程式碼閱讀加 candidate 數量實測，沒有做 13 台裝置的端到端重現。
- 建議：
  - 已驗證的主機改用依 peer 數量放大的額度（例如 `RATE_MAX × (1 + peers)`），或把 candidate 合併送出。
  - 主機每次載入頁面產生一個 instance id，隨 `host-auth` 送給伺服器，伺服器在 `host-online`／`welcome` 轉帶。peer 只在 instance 改變時才重連。協定規格 7 也要一起改。
  - 補測試：20 個假 peer 同時重連不會觸發 4008；主機的 WebSocket 重連時，已開啟的直連不會被關閉。

### 需求、架構、安全、品質
- **架構**：`lib/` 只改了 `version.js`，核心沒有匯入 solutions；沒有 `package.json`，也沒有建置步驟；路徑都是相對路徑，用 `document.baseURI` 組網址；SW 版本已更新（`--check` 通過）；`server/` 排除在 SW 雜湊之外是對的。
- **安全**：
  - 授權只存 SHA-256；比對用固定時間比較；查詢 token 以 HMAC 推導；送單時在 transaction 內重讀授權，撤銷立即生效。
  - `authorizeMethod` 的角色表正確；`actor` 由主機依授權填入。
  - 主機席位用 TOFU 綁定；主機端的 `sig` 要確認。
  - XSS 沒有發現問題：`unsafe` 只用在 QR Code 的 SVG；裝置名稱等遠端傳來的字串都經過 `html` 跳脫。
  - 主要缺口是 M1、S1、S5。
- **正確性**：
  - IndexedDB 的寫入都在單一 transaction 內完成；`order.act` 依序執行。
  - 背壓處理正確，`rev` 跳號會觸發重讀。
  - 資源都在 `disconnectedCallback` 釋放（主機、hub、links、信令、計時器、`beforeprint`）；監聽器都在 `afterFirstRender` 綁定；`details` 的展開狀態用 capture 的 `toggle` 記住。
- **跨 Task 重複**：
  - `isOriginAllowed`、`hostPageLink` 和 base64url 在 Node 與 Worker 各有一份，因為兩者都必須是單一檔案，目前內容相同，沒有分歧。
  - 管理頁的角色名稱對照重複（N8）。
  - 沒有發現行為已分歧的重複。
